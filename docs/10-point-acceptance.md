# RecallOps 10/10 acceptance standard

This is an engineering target, not a prediction of subjective judge scores. A category is
reported as complete only when every listed claim has reproducible evidence. Unknowns and
externally blocked submission actions remain explicit.

## Originality and product thesis

- Outcome-conditioned, governed memory is visibly distinct from similarity-only RAG.
- Approval, execution evidence, observation, review, and recall form one enforced causal loop.
- The demo proves abstention for stale, unsafe, cross-tenant, unreviewed, and incompatible data.

## CockroachDB integration

- Transactions, vector search, governance history, tenant boundaries, and outbox delivery use
  CockroachDB for essential behavior rather than branding.
- Query plans and live tests prove filtered vector retrieval and schema invariants.
- A second eligible CockroachDB capability is demonstrated and evidenced under official rules.

## AWS integration

- Bedrock participates in bounded reasoning and embedding with auditable model provenance.
- HTTPS/OIDC, ECS, S3, CloudWatch, Secrets Manager, networking, and least-privilege IAM are
  reproducibly deployed and verified.
- Dependency outages fail safely; no fallback crosses semantic spaces or invents evidence.

## Technical depth and agent quality

- The agent uses typed, bounded, read-only tools and emits a replayable plan and trace.
- Retrieval abstention is calibrated on held-out data with thresholds, margins, and evidence
  quality gates.
- Mutating actions cannot bypass approval and execution attestation.

## Evidence quality

- At least 100 real-text cases exercise live Titan embeddings and CockroachDB queries.
- Independent labels, a held-out split, confidence intervals, ablations, calibration, latency,
  cost, and error analysis are published with reproducible commands.
- Reports never substitute hand-authored candidate scores for end-to-end measurements.

## Production readiness

- Tenant isolation is enforced in application and database invariants.
- Transactional outbox delivery, idempotent consumers, retry/repair, migration serialization,
  availability, observability, security headers, prompt-injection tests, and restore procedures
  are verified.
- Threat model, privacy/retention, accessibility, cost, operational simplicity, and cleanup are
  documented without unsupported production claims.

## Judge experience and submission

- A new judge completes the core loop in under three minutes with no local setup.
- Public source, live demo, architecture, evidence dashboard, concise video, and Devpost text
  agree with the deployed system.
- The final audit checks every official rule and required field against primary sources.

## Non-negotiable release gates

1. Unit, integration, migration, authorization, concurrency, resilience, and browser tests pass.
2. Formatting, lint, strict typing, dependency/security scans, and infrastructure validation pass.
3. Live smoke tests capture immutable evidence for each material cloud/database claim.
4. Documentation is reconciled after deployment, not before it.
5. Subjective scores, synthetic results, and unavailable operating history are never presented as
   objective proof.
